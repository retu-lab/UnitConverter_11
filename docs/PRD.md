## 1. 개요

### 1.1 한 줄 요약

인테리어 시공 현장에서 **서로 다른 단위·기준으로 적힌 치수**를 손으로 맞출 때 발생하는 **판정·재확인 비용**과 **발주·견적 오차**를 줄이기 위해, meter / feet / yard 간 **일관된 SSOT 변환**을 제공하는 CLI 기반 단위 변환 프로그램.

### 1.2 배경

현장 반장은 해외·국내 자재 카탈로그를 동시에 보며 yard/feet 도면과 meter 기준 견적·발주를 같은 마감 안에 맞춰야 한다. Mom Test 인터뷰(2025-05-22 사례)에서 **예상 30분 작업이 약 4시간**으로 늘어나고, 견적 **2회 발송·팀 재설명**이 발생한 것이 확인되었다.

### 1.3 제품이 해결하려는 것 (솔루션이 아닌 결과)

| Mom Test Pain | 제품 기여 방향 |
|---------------|----------------|
| 변환 비율 기억·검색 의존 (0.9m vs 0.91m, 3.28 vs 3.28084) | SSOT 상수 + 테스트로 **재현 가능한 동일 결과** |
| 11.43m vs 12.57m — 순수 환산 vs 여유분 혼선 | **순수 환산값**을 정확히 제공해 보내기 전 판정 지원 |
| 계산기 "한 번에 한 단위만" | 한 입력으로 meter·feet·yard **동시 출력** |
| 견적 발송 후 업체 지적 (~35분) | 입력 검증 + 정확 변환으로 **보내기 전** 오류 차단 |
| 메모·엑셀·구두로 기준별 숫자 재설명 | 출력에 단위·값 명시로 기준 혼선 최소화 |

## 3. 문제 정의 (Mom Test)

### 3.1 표면 문제 (PRD에 반영하지 않음)

다음은 솔루션이 섞인 **잘못된 문제 정의**이며, 요구사항의 근거로 사용하지 않는다.

- ~~"yard/meter/feet 단위를 자동으로 바꿔 주는 변환 프로그램을 만든다."~~
- ~~"현장용 단위 변환 앱을 개발해서 견적 시간을 줄인다."~~

### 3.2 진짜 문제 (한 문장)

**서로 다른 단위·기준(도면 yard / 견적 meter / 여유분 적용 순서)으로 적힌 치수를 사람이 손으로 맞추다 보니, 어떤 숫자가 '맞는 값'인지 판단·재확인에 시간이 크게 들고, 그 사이 발주·견적·현장 공유 숫자가 어긋난다.**

### 3.3 Mom Test 증거

| # | 인터뷰 인용 | 시사점 |
|---|-------------|--------|
| 1 | "팀원한테 물어봤는데, 한 명은 '약 0.9m', 다른 한 명은 '0.91m 정도'라고 답했어요." | 변환 비율 불확실·출처 불일치 |
| 2 | "업체에서 '12.5 yard면 11.43m 맞는데, 12.57m는 어디서 나온 숫자냐'고 물어봤어요." | 순수 환산 vs 여유분 포함 값 구분 실패 |
| 3 | "원래 9시 반쯤 끝날 줄 알았던 작업이 거의 4시간 걸렸어요." | 확인·재작업 시간 과다 |
| 4 | "변환 공식은 매번 검색해요. 어떤 사이트는 3.28, 어떤 건 3.28084라서 헷갈려요." | 비율 출처 불일치 (워크북) |
| 5 | "계산기 앱은 한 번에 한 단위만 바꿔줘서, meter → feet → yard 세 줄을 각각 다시 입력해야 해요." | 반복 입력 비용 (워크북) |

### 3.4 대표 사례 (2025-05-22)

| 구분 | 내용 |
|------|------|
| **장소** | 강남 오피스 리모델링 3층 |
| **목표** | 바닥재 발주 수량 확정 → 오후 2시 마감 견적 제출 |

## 4. R-G-I-O

| | 내용 |
|---|---|
| **R — Role** | 인테리어 시공팀 현장 반장. 해외 yard/feet 도면과 국내 meter 견적·발주를 같은 날·같은 마감 안에 맞춰야 함. |
| **G — Goal** | 도면 치수를 견적·발주에 쓸 기준 단위(meter)로 맞춰 **수량을 확정**하고, **마감 전** 업체·팀에 제출. |
| **I — Issue** | 도면 yard / 견적 meter / 여유분 적용 순서가 섞인 채 손으로 변환하면 **어느 숫자가 '맞는 값'인지 즉시 판단·재확인**에 시간이 크게 들고, 그 사이 **발주·견적·현장 공유 숫자가 어긋남**. |
| **O — Outcome** | **한 기준으로 확정된 치수**를 견적·발주·현장 공유까지 **재작업·재설명 없이** 일관되게 사용. |

## 6. 사용자 시나리오

### 6.1 주 시나리오 — yard 도면 → meter 견적

**Given** 도면에 `12.5 yard`만 표기되어 있고, 국내 업체 견적 양식은 meter 기준  
**When** 현장 반장이 변환 프로그램에 `yard:12.5` 입력  
**Then** SSOT 비율로 meter·feet·yard 결과가 **동일 기준**으로 출력되어, 순수 환산 meter(11.43m)를 견적 기준으로 즉시 사용 가능

### 6.2 부 시나리오 — 검색·팀원 확인 대체

**Given** 변환 비율을 기억하지 못하거나 팀원마다 다른 답(0.9m vs 0.91m)이 나옴  
**When** 프로그램이 `METER_TO_YARD` 등 **단일 SSOT 상수**로 계산  
**Then** 검색·구두 확인 없이 **재현 가능한 동일 결과** 확보

### 6.3 부 시나리오 — 잘못된 입력 조기 차단

**Given** 피로·급박으로 `meter:abc`, `unknown:1`, 음수 등 잘못된 입력  
**When** CLI에서 형식·단위·값 검증  
**Then** 견적 발송 전 오류를 인지하고 재입력 (발주 오차 예방)

| **FR-LOC-02** | `meter` 길이 값을 `yard`로 SSOT 비율(`1.09361`) 적용해 **정확히** 변환 | P0 | yard 도면 → meter 견적 핵심 경로 |
| **FR-LOC-03** | feet / yard 입력 시 meter 기준으로 환산 후 **세 단위 동시 출력** | P0 | 계산기 "한 번에 한 단위만" 불편 대응 |

**입력 형식:** `단위:값` (예: `meter:2.5`)

**출력 예시:**

```
2.5 meter = 2.5 meter
2.5 meter = 8.2021 feet
2.5 meter = 2.734025 yard
```

> **참고:** 여유분(10%) 적용은 **변환과 별도 비즈니스 규칙**이다. v1.0은 순수 환산값을 정확히 제공하여 SC-2(11.43m vs 12.57m 판정)를 지원한다. 여유분 계산 UI는 후속 범위.

## 9. 도메인 상수 (SSOT)

| 상수 | 값 | 용도 |
|------|-----|------|
| `METER_TO_FEET` | `3.28084` | meter ↔ feet |
| `METER_TO_YARD` | `1.09361` | meter ↔ yard |

- feet ↔ yard 간 변환은 **meter 기준**으로 계산한다.
- Mom Test에서 확인된 "3.28 vs 3.28084" 혼란을 제거하기 위해 **3.28084를 프로젝트 SSOT**로 고정한다.

| 계산기 한 단위씩 입력 | 한 입력으로 meter·feet·yard 동시 출력 |
