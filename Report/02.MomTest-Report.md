## 2. Mom Test 워크북 (사전 정의)

### 인터뷰 답변 (과거 사실 — 사전 가설)

- "지난 **3월 12일** 부분 마방jin 과제 **23:59 마감**인데, **오후 7시부터 10시반**까지 막혀 있었어요."
- "**19:35**에 실행해 보니 **대각선 하나만** 합이 15가 아니었는데, **코드가 틀린 건지 손계산이 틀린 건지** 헷갈렸어요."
- "공책에 3×3 표를 **네 번** 다시 그렸어요. 한 번은 화면 숫자를 잘못 옮겨 적어서 **15분을 헛돌았**어요."
- "두 번째 테스트 케이스(가운데 5만 채워진 격자)에서 **while**가 **3과 7을 번갈아** 출력했어요."
- "**22:18**에 '첫 예시는 돌아가니까 0점은 아닐 것'이라고 판단하고 **테스트2 미완**으로 제출했어요."

### 표면 문제 (금지 — 솔루션 섞인 문장)

- ~~"부분 마방jin **자동 완성 프로그램**을 만들어야 해."~~
- ~~"행·열·대각선 합을 **한눈에 검증해 주는 디버거**가 있으면 좋겠어."~~
- ~~"**while 루프 검증 도구**를 쓰면 두 번째 테스트도 통과할 거야."~~

### 진짜 문제 (사전 가설 — 한 문장)

**과제 PDF의 ‘어떤 줄까지 15로 맞춰야 하는지’와 내가 짠 로직·손계산이 같은 기준인지 확신하지 못한 채, 출력·공책·PDF를 번갈아 대조하다 보니 어느 칸·어느 줄이 깨졌는지 한 번에 짚지 못하고, 마감 앞에서 일부 케이스만 맞는 상태로 제출하는 선택을 했다.**

## 3. Mom Test 인터뷰 기록

**역할:** 인터뷰어 — 과목 TA / 응답자 — 학생 박서연  
**규칙:** 명확한 답변, 솔루션 언급 금지  
**턴 수:** 3턴 (질문 → 답 × 3)

### Turn 1 — 질문 1

> 마지막으로 부분 마방jin 과제 때문에 **제출 직전까지 막혔던 게** 언제였어? 그날 **처음 뭘 하려다가** 시작했는지, **처음부터 끝까지** 순서대로 말해 줘.

#### 답변 요약

| 항목 | 내용 |
|------|------|
| **일시** | 3월 12일(수) 저녁, 기숙사 |
| **처음 하려던 일** | `fill_magic_square()` 완성 — 빈 칸 3개 채워 행·열·대각선 합 15 |
| **마감** | 23:59 |

#### 순서 (타임라인)

1. **19:05** — PDF 재독. 마방 상수 15 확인, **유도 과정은 생략**.
2. **19:20** — `(0,2)`, `(1,0)`, `(2,1)`에 15에서 기존 칸을 빼는 방식으로 값 입력.
3. **19:35** — 대각선 하나만 합 ≠ 15. **코드 vs 손계산** 구분 불가.
4. **19:50** — 공책 손계산 → `(2,1)`을 7→9로 수정 필요 확인.
5. **20:15** — 수정 후 **첫 행 합 17**. 격자를 메모장·공책·화면 **3곳**에 대조.
6. **20:40** — 카톡 "대각선도 15?" → PDF 2페이지 재확인.
7. **21:10** — 테스트2(가운데 5만 채움)에서 **while 무한 반복**처럼 동작.
8. **22:30** — 테스트1만 통과 상태로 제출. **예상 1시간 → 약 3시간 30분**.

---

### Turn 2 — 질문 2 (추궁)

> 19:35에 대각선 합이 안 맞았을 때부터 20:15에 첫 행이 17로 나올 때까지 **40분 가까이** 걸렸잖아. 그동안 **뭐가 틀렸는지** 어떻게 찾고 있었어? **손계산, 출력 비교, PDF, 카톡** 중 어디에 시간이 가장 많이 갔어?

#### 답변 요약

**40분 중 대략:** 오류 위치 모름 ~15분 / 손계산 반복 ~20분 / PDF·카톡 ~5분

#### 단계별 원인

| 구간 | 시간 | 상황 |
|------|------|------|
| **1. 오류 위치 모름** | ~15분 | `print`로 **행만** 출력. 열·대각선 미확인. |
| **2. 손계산 반복** | ~20분 | 공책 격자 **4회** 재작성. 1회는 화면→공책 전사 오류로 **15분 낭비**. |
| **3. PDF·카톡** | ~5분 | PDF "대각선 포함" 확인. 카톡은 답 못 얻음. |

#### 틀린 걸 찾는 방식

| 시각 | 행동 |
|------|------|
| 19:35~19:50 | 출력만 믿다가 손계산으로 `(2,1)` 수정 |
| 20:00~20:15 | `(2,1)` 수정 후에도 첫 행 17 → `(0,2)` vs `(2,1)` **한 칸씩** 손검증 |
| **핵심** | 한 칸 수정 시 **다른 줄 연쇄 깨짐** 판단 불가 → 공책 매번 새로 작성 |

### Turn 3 — 질문 3 (추궁)

> 21:10에 두 번째 테스트 케이스에서 막혔을 때, **23:59 전에** 그 케이스까지 맞추려다 **포기하고 첫 예시만 제출**하기로 한 **정확한 순간**이 언제였어? 그때까지 **어디까지 했고**, 포기한 뒤엔 **뭘 대신** 했어?

#### 답변 요약

| 항목 | 내용 |
|------|------|
| **포기 시각** | 22:18 |
| **그때까지** | while로 빈 칸 채움 → 3/7 번갈아 출력 → break·합 검사 조건 **3회** 변경 |
| **외부 확인** | 조교 메일 불가, 룸메이트 10분만 "while 조건 이상" |
| **포기 이유** | 테스트1 통과 → 0점 회피 판단 |
| **포기 후** | README "테스트2 미완" + 스크린샷 제출 → 제출 후에도 공책 손계산 **12분** 추가 |
| **결과** | 테스트1 10점 / 테스트2 0점 |

**감점 요인 (−1):** 진짜 문제 문장에 PDF 규칙 / 손계산 / 코드 출력의 **3-way 기준**이 yard·meter·여유분 수준으로 명시적으로 대응되지 않음.

**고칠 질문 1개 제안 (Turn 3):**

> 21:10부터 22:18까지 while 출력이 **3과 7을 번갈아** 보일 때, **몇 시 몇 분에** `break`나 합 검사 조건을 **몇 번** 바꿨는지, **그때마다** 화면 출력이 **어떻게 달라졌는지** 순서대로 말해 줘.

**이유:** 포기 시점·대체 행동보다 **조건 변경 → 출력 변화**의 시간순 반복을 묶으면 Mom Test **판정·재현** 증거가 더 쌓임.
