## 한 장 요약 — Cursor는 이렇게 쌓인다

```
┌─────────────────────────────────────────────────────────┐
│  ① R-G-I-O        ← 매번 채팅에 적는 "일 지시서"          │
├─────────────────────────────────────────────────────────┤
│  ② Model          ← AI 두뇌 (Auto / 특정 모델 선택)      │
│  ③ Agent          ← Model + Tool을 묶은 "일꾼"           │
│  ④ Harness        ← Agent 주변 실행 환경 (터미널·파일·권한) │
├─────────────────────────────────────────────────────────┤
│  ⑤ Rule           ← 항상 지켜야 할 프로젝트 규칙          │
│  ⑥ Skill          ← 특정 작업 절차서 (필요할 때만)        │
│  ⑦ Command        ← `/` 로 불러오는 저장된 프롬프트       │
├─────────────────────────────────────────────────────────┤
│  ⑧ Tool / MCP     ← AI가 직접 쓰는 손·발 (파일·GitHub…)  │
├─────────────────────────────────────────────────────────┤
│  + Test Loop      ← "만들고 → 테스트 → 고친다" 반복       │
│  + Hook           ← Agent 행동 전·후 자동 스크립트        │
└─────────────────────────────────────────────────────────┘
```

**기억할 것 3가지**

| # | 원칙 | 이유 |
|---|------|------|
| 1 | **위에서 아래로** — R-G-I-O → Rule/Skill → Agent 실행 | 지시가 흐려지면 코드도 흐려진다 |
| 2 | **Rule은 짧게, Skill은 절차로** | Rule = "항상", Skill = "이 작업할 때만" |
| 3 | **Test Loop는 프롬프트에 명시** | "테스트 통과할 때까지"를 말하지 않으면 AI가 멈춘다 |

## ① R-G-I-O — 채팅창에 쓰는 일 지시서

Mom Test에서 뽑은 **진짜 문제**를 Cursor에게 넘길 때 쓰는 4줄 템플릿.

| 글자 | 의미 | UnitConverter 예시 |
|------|------|-------------------|
| **R** Role | 누가 / 어떤 코드 | Python TDD 실습 중인 개발자. `UnitConverter.py` 리팩터링 |
| **G** Goal | 이번에 끝낼 것 | meter/feet/yard 변환 + OCP 설계 + pytest 통과 |
| **I** Issue | 막히는 이유 (솔루션名 X) | 단위 추가할 때마다 if-else가 늘고, 테스트 없이 수동 확인 |
| **O** Outcome | 완료 판정 | `pytest` green, 새 단위 추가 시 기존 코드 수정 0줄 |

### 복사해서 쓰는 프롬프트 (UnitConverter STEP 2)

```
R: Python UnitConverter 실습. OCP·SRP·pytest.
G: meter/feet/yard 변환 + 입력 검증 + 테스트 통과.
I: 단위 추가 시 main() if-else 수정, 테스트 없음.
O: pytest green, 새 단위 추가 시 기존 클래스 변경 없음.
```

### 성공 기준 (Report/03에서 이어옴)

| # | 기준 | Cursor에서 확인 방법 |
|---|------|---------------------|
| 1 | 변환 로직 정확 | `pytest tests/` |
| 2 | OCP — 새 단위 추가 시 기존 코드 미수정 | "cubit 추가해줘" 후 diff 확인 |
| 3 | 입력 검증 (음수·형식·없는 단위) | 테스트 + `python UnitConverter.py` 수동 입력 |
| 4 | Report/Prompting Export | Agent에게 "Report·Prompting 폴더에 04번으로 저장" |

## ② Model — AI 두뇌 선택

| 모드 | 언제 쓰나 | UnitConverter 예 |
|------|-----------|-----------------|
| **Auto** | 일반 구현·리팩터·테스트 | OCP 인터페이스 설계, pytest 작성 |
| **특정 모델** | 긴 설계·어려운 버그 | while 루프 dead code, 순환 의존 |
| **Ask (읽기 전용)** | 코드 이해·질문만 | "현재 main() 흐름 설명해줘" |

**실무 팁:** 구현은 Agent(Auto), **구조 설계만** 먼저 물어볼 때 Ask.

---

## ③ Agent — Model + Tool을 묶은 일꾼

Agent = 채팅에서 **파일 수정·터미널·검색**까지 스스로 하는 모드.

| Agent 모드 | 하는 일 | UnitConverter 예 |
|------------|---------|-----------------|
| **Agent** | 코드 작성·실행·테스트 | `UnitConverter.py` 리팩터 + pytest 실행 |
| **Plan** | 설계만, 코드 X | "OCP 클래스 다이어그램 먼저" |
| **Debug** | 실패 원인 추적 | pytest red → 원인·수정 |

**실무 팁:** 한 번에 너무 많이 시키지 말 것.

```
❌ "OCP 리팩터 + JSON 설정 + CSV 출력 + Hook + MCP 전부"
✅ "1) OCP 리팩터 + pytest  2) JSON 설정  3) CSV 출력" (3턴)
```

---

## ④ Harness — Agent가 돌아가는 환경

Harness = IDE가 Agent에게 주는 **실행 환경** (직접 설정하는 것이 아님).

| 제공 기능 | Agent가 쓰는 방법 | 확인 |
|-----------|------------------|------|
| 터미널 | `pytest`, `python UnitConverter.py` | Agent가 직접 실행 |
| 파일 읽기/쓰기 | `UnitConverter.py`, `tests/` | diff로 검토 |
| Git | status, diff, commit (요청 시) | 커밋은 **명시적으로** 요청 |
| 샌드박스 | 네트워크·권한 제한 | push 실패 시 권한 승인 |

**실무 팁:** "테스트 돌려서 green 될 때까지"라고 쓰면 Harness(터미널)까지 Agent가 알아서 씀.

## ⑤ Rule — 프로젝트 규칙 (항상 적용)

**위치:** `.cursor/rules/*.mdc`

| Rule 종류 | 예시 | UnitConverter |
|-----------|------|---------------|
| alwaysApply | 코딩 스타일, 커밋 금지 | "커밋은 사용자가 요청할 때만" |
| globs | 특정 파일만 | `**/*.py` → pytest 필수, type hint |

### 예시 Rule (`.cursor/rules/python-tdd.mdc`)

```markdown
---
description: Python TDD·OCP 규칙 (UnitConverter)
globs: **/*.py
alwaysApply: false
---

- 새 기능은 테스트 먼저 또는 동시에 작성
- 단위 추가 시 main() if-else 확장 금지 — Converter 인터페이스 사용
- magic number 금지 — constants 또는 설정 파일
```

**Rule vs R-G-I-O:** Rule = 저장된 규칙(매 세션), R-G-I-O = 이번 작업 지시(매 채팅).

## ⑧ Tool / MCP — AI의 손과 발


## Test Loop — 만들고 → 테스트 → 고친다

Cursor에서 TDD를 돌리는 **표준 프롬프트 패턴**.

```
UnitConverter meter→feet 변환 테스트 추가.
pytest 실행 → 실패하면 수정 → green 될 때까지 반복.
완료 후 변경 파일 목록만 출력.
```

### Test Loop 체크리스트

| 단계 | Agent 행동 | 당신이 할 일 |
|------|-----------|-------------|
| 1 Red | 실패 테스트 작성 | 테스트 의도 맞는지 확인 |
| 2 Green | 최소 구현 | 과도한 리팩터 diff 거부 |
| 3 Refactor | OCP/SRP 정리 | public API 변경 없는지 확인 |
| 4 Repeat | 다음 요구사항 | README 요구사항 하나씩 |

### UnitConverter 권장 테스트 순서

1. `meter → feet` (3.28084)
2. `meter → yard` (1.09361)
3. 잘못된 입력 (음수, `abc:1`, `meter:abc`)
4. 동적 단위 등록 (추가 요구사항)
5. JSON/CSV 출력 (추가 요구사항)

## Hook — Agent 행동 전·후 자동화

**위치:** `.cursor/hooks.json` + `.cursor/hooks/*`

| 이벤트 | 쓰임 | UnitConverter 예 |
|--------|------|-----------------|
| `afterFileEdit` | 저장 후 포맷 | `*.py` → black/ruff |
| `beforeShellExecution` | 위험 명령 차단 | `rm -rf`, force push 차단 |
| `postToolUse` (pytest) | 실패 시 follow-up | "테스트 실패, 수정해" 자동 주입 |
| `beforeSubmitPrompt` | 비밀번호·토큰 검사 | `.env` 내용 붙여넣기 경고 |

### 최소 Hook 예시 — pytest 후 알림

`.cursor/hooks.json`:

```json
{
  "version": 1,
  "hooks": {
    "afterShellExecution": [
      {
        "command": ".cursor/hooks/after-test.sh",
        "matcher": "pytest"
      }
    ]
  }
}
```

**실무 팁:** Hook은 **나중에** 추가. 먼저 R-G-I-O + Test Loop로 익숙해진 뒤, 반복 작업만 Hook으로.
