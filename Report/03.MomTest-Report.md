## 2. Mom Test 인터뷰 (질문 1)

### 질문 1

> 마지막으로 현장에서 yard 단위 도면을 meter나 feet로 바꾼 게 언제였어? 그때 **처음 뭘 하려다가** 시작했는지, **처음부터 끝까지** 순서대로 말해 줘.

### 답변 요약

| 항목 | 내용 |
|------|------|
| **일시** | 지난달 5월 22일(수) 오전, 강남 오피스 리모델링 3층 |
| **처음 하려던 일** | 바닥재 발주 수량 확정 → 오후 2시 마감 견적 제출 |
| **도면 수치** | 바닥 12.5 yard, 커튼 트랙 8 yard (yard만 표기) |

#### 순서 (타임라인)

1. **09:10** — 도면 PDF 확인. yard 단위만 표기됨.
2. **09:15** — 국내 업체 견적 양식이 meter 기준이라 yard → meter 변환 필요 판단.
3. **09:20** — 변환 비율 기억 불확실. 팀원 A "약 0.9m", 팀원 B "0.91m 정도".
4. **09:25** — 스마트폰으로 "yard meter 변환" 검색 → 0.9144 확인, 메모.
5. **09:30** — 12.5 × 0.9144 = 11.43m, 8 × 0.9144 = 7.32m 계산.
6. **09:35** — 바닥재 여유 10% 적용: 11.43 × 1.1 = 12.57m.
7. **09:40** — 견적서에 12.57m 기재 후 발송.
8. **10:15** — 업체 전화: "12.5 yard = 11.43m 맞는데 12.57m는 어디서?" → 여유분 적용 순서 혼란.
9. **10:20~10:40** — yard 기준 여유 vs meter 환산 후 여유 순서 재확인. 손계산 반복.
10. **10:40** — 견적 철회 후 13.75 yard → 12.57m 기준으로 재발송.
11. **11:30** — 시공팀, 커튼 7.32m 적정성 문의 → 도면 feet/inch 표기 재확인.
12. **13:00** — 발주 숫자 팀 공유 완료. 예상 30분 → **약 4시간** 소요.

## 3. 질문 1 답변 — 사실성 평가

| 항목 | 판정 | 근거 |
|------|------|------|
| **시간·장소 구체성** | ✅ 높음 | 5/22(수) 09:10~13:00, 강남 오피스 3층 — 분 단위 타임라인 |
| **행동 순서** | ✅ 높음 | 도면 확인 → 변환 필요 판단 → 팀원 질문 → 검색 → 계산 → 여유분 → 견적 → 업체 지적 → 재계산 |
| **숫자 일관성** | ✅ 높음 | 12.5 yard × 0.9144 = 11.43m, ×1.1 = 12.57m — 계산·역산(13.75 yard) 모순 없음 |
| **현장 맥락** | ✅ 높음 | 견적 마감(14:00), 국내 업체 meter 양식, yard-only 도면 — 인테리어 현장 반장 행동과 부합 |
| **Mom Test 준수** | ✅ | 과거 사실·구체적 행동만, 솔루션·앱 언급 없음 |

**종합: 사실성 9/10** — 현장 반장이 겪을 법한 흐름. "예상 30분 → 4시간"은 추궁 질문으로 추가 검증 필요.

### 추궁 질문 1개 (제안)

> 업체 전화로 숫자가 이상하다는 걸 알았을 때(10:15)부터 견적을 다시 맞출 때(10:40)까지 **몇 시부터 몇 시까지** 걸렸고, 그동안 **메모·검색·엑셀·팀 확인** 중 뭘 **어떤 순서로** 반복했어?

### 불편 요약

1. **변환 비율 불확실** — 팀원마다 0.9m vs 0.91m, 매번 검색(0.9144)에 의존
2. **기준 혼선** — 도면 yard / 견적 meter / 여유분 적용 순서가 섞여 11.43m vs 12.57m 중 어느 게 맞는지 즉시 판단 불가
3. **오류 발견 지연** — 견적 발송 후 업체 전화까지 ~35분, 틀렸다는 걸 스스로 못 잡음
4. **시간·재작업 비용** — 30분 예상 → 약 4시간, 견적 2회 발송, 도면·팀 재확인
5. **공유·설명 부담** — 같은 숫자를 기준별로 두 번 이상 설명해야 함

### 진짜 문제 (한 문장)

**서로 다른 단위·기준(도면 yard / 견적 meter / 여유분 적용 순서)으로 적힌 치수를 사람이 손으로 맞추다 보니, 어떤 숫자가 '맞는 값'인지 판단·재확인에 시간이 크게 들고, 그 사이 발주·견적·현장 공유 숫자가 어긋난다.**

### Mom Test 증거 3줄 (인터뷰 답 인용)

1. "팀원한테 물어봤는데, 한 명은 '약 0.9m', 다른 한 명은 '0.91m 정도'라고 답했어요."
2. "업체에서 '12.5 yard면 11.43m 맞는데, 12.57m는 어디서 나온 숫자냐'고 물어봤어요."
3. "원래 9시 반쯤 끝날 줄 알았던 작업이 거의 4시간 걸렸어요."

## 5. R-G-I-O + 주제 + 성공 기준

### R-G-I-O

| | 내용 |
|---|---|
| **R — Role (누가)** | 인테리어 시공팀 **현장 반장** 김민수. 해외 yard/feet 도면과 국내 meter 견적·발주를 같은 날·같은 마감 안에 맞춰야 함. |
| **G — Goal (무엇을 하려는지)** | 도면 치수를 **견적·발주에 쓸 기준 단위(meter)** 로 맞춰 **수량을 확정**하고, **마감 전** 업체·팀에 제출. |
| **I — Issue (진짜 문제)** | **도면 yard / 견적 meter / 여유분 적용 순서**가 섞인 채 손으로 변환하면 **어느 숫자가 '맞는 값'인지 즉시 판단·재확인**에 시간이 크게 들고, 그 사이 **발주·견적·현장 공유 숫자가 어긋남**. |
| **O — Outcome (바라는 결과)** | **한 기준으로 확정된 치수**를 견적·발주·현장 공유까지 **재작업·재설명 없이** 일관되게 사용. |

### 주제 (1문장)

**현장에서 단위·기준이 섞인 치수를 손으로 맞출 때, 숫자 판정·재확인 비용과 발주·견적 오차가 발생한다.**

### 성공 기준

| # | 기준 | Mom Test 근거 |
|---|------|----------------|
| 1 | **시간** — yard→meter 견적·여유분 포함 작업이 **30분 이내**에 확정된다. (현재: 예상 30분 → **약 4시간**) | "원래 9시 반쯤 끝날 줄 알았던 작업이 거의 4시간 걸렸어요." |
| 2 | **판정** — 11.43m vs 12.57m처럼 **기준이 다른 두 숫자**를 업체·팀에 보내기 전에 **스스로 어느 쪽이 맞는지** 판단할 수 있다. | "12.5 yard면 11.43m 맞는데, 12.57m는 어디서 나온 숫자냐" |
| 3 | **재작업** — 견적 **재발송 0회**, 같은 숫자에 대한 **단톡·전화 재설명 0회**. | 10:40 견적 철회·재발송, 11:20~12:50 팀 재설명 |
| 4 | **일관성** — 도면 yard / 순수 환산 meter / 여유 포함 meter가 **각각 구분**되어 팀·업체에 **한 번에** 전달된다. | 메모·엑셀·구두로 기준별 숫자를 두 번 설명 |

> 성공 기준은 솔루션(앱·프로그램)이 아니라 **현장 반장이 체감하는 결과** 기준으로 작성.
