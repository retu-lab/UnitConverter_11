## 1. 세션 배경

`Report/04.CursorAI-Report.md`에서 **⑦ Command**는 "자주 쓰는 프롬프트를 `/`로 불러온다"고 소개했지만, 세션마다 반복하는 **Report + Transcript Export** 작업은 아직 수동 프롬프트였다.

이번 세션에서 다음을 한 번에 정리했다.

1. Command **작성·등록** 방법 (파일 vs Settings)
2. 프로젝트 **01.XXX 명명 규칙**과 번호 자동 증가
3. 실제 Command 파일 **생성·이름 단순화** (`/export`)

---

## 2. Command 등록 방법 비교

| 방식 | 위치 | 장점 | 단점 |
|------|------|------|------|
| **파일 (권장)** | `.cursor/commands/*.md` | Git 공유, 팀 표준화 | 폴더·파일 직접 생성 |
| **Settings UI** | Cursor Settings → Commands | GUI로 빠른 등록 | 개인 설정, repo 미포함 |

**핵심 규칙:** 파일명 = 명령어 이름. `export.md` → `/export`. 파일 전체가 Agent 프롬프트가 된다.

---

## 3. 프로젝트 Export 명명 규칙

| 폴더 | 형식 | 예시 |
|------|------|------|
| `Report/` | `NN.<주제>-Report.md` | `05.Command-Export-Report.md` |
| `Prompting/` | `NN.Export-Transcript.md` | `05.Export-Transcript.md` |

- `NN`: 두 자리 (01, 02, …)
- Report·Prompting **같은 번호** 사용
- Command가 폴더 스캔 후 **최대 번호 + 1** 자동 결정
- `/export 05`처럼 번호를 인자로 넘길 수 있음

---

## 4. 생성된 Command — `/export`

**경로:** `.cursor/commands/export.md`

### Command가 시키는 일

1. `Report/`, `Prompting/` 목록 확인 → NN 결정
2. 이번 대화 맥락으로 **Report** 작성 (기존 01·04 스타일 참고)
3. Turn별 **Export Transcript** 작성 (기존 01·04 스타일 참고)
4. 생성 경로 2개만 출력 (커밋·push는 요청 시만)

### 실행 예

```
/export
/export 06
```

## 6. Cursor 8계층에서의 위치

```
⑦ Command (/export)
    ↓ 프롬프트 주입
③ Agent + ④ Harness
    ↓ Read/Write Tool
⑧ Tool — Report/, Prompting/ 파일 생성
```

- **Rule** 없이도 Command만으로 반복 작업 표준화 가능
- **Skill**(`export-transcript`)과 유사하나, Command는 **사용자가 `/`로 명시 호출**
