**User:**
```
UnitConverter Mom Test. 페르소나: 인테리어 시공팀 현장 반장.
Mom Test 규칙 준수. 질문 1개만. 솔루션 금지.
```

**Assistant:**
- 역할: 시공팀 관리자(인터뷰어) → 사용자: 현장 반장
- **질문 1:** 마지막으로 현장에서 yard 단위 도면을 meter나 feet로 바꾼 게 언제였어? 그때 **처음 뭘 하려다가** 시작했는지, **처음부터 끝까지** 순서대로 말해 줘.

## Turn 2 — [답변] 사실성 평가 + 추궁 + 불편 요약

**User:**
```
[답변] → 사실성 평가 + 다음 추궁 1개 + 불편 요약
```

**Assistant (요약 출력):**
- **사실성: 9/10** — 시간·장소·행동 순서·숫자 일관성·현장 맥락 모두 높음
- **추궁 1개:** 10:15~10:40 구간, 메모·검색·엑셀·팀 확인을 **어떤 순서로** 반복했는지
- **불편 5건:** 변환 비율 불확실 / 기준 혼선 / 오류 발견 지연 / 시간·재작업 / 공유·설명 부담

## Turn 3 — 인터뷰 종료

**User:**
```
인터뷰 종료 → 표면 vs 진짜 문제 1문장 + Mom Test 증거 3줄
```

**Assistant:**
1. **표면 문제:** ~~변환 프로그램~~ / ~~단위 변환 앱~~
2. **진짜 문제:** 서로 다른 단위·기준(도면 yard / 견적 meter / 여유분 적용 순서)으로 치수를 손으로 맞추다 보니 판단·재확인에 시간이 크게 들고 발주·견적·현장 공유 숫자가 어긋난다.
3. **증거 3줄:**
   - "팀원한테 물어봤는데, 한 명은 '약 0.9m', 다른 한 명은 '0.91m 정도'라고 답했어요."
   - "업체에서 '12.5 yard면 11.43m 맞는데, 12.57m는 어디서 나온 숫자냐'고 물어봤어요."
   - "원래 9시 반쯤 끝날 줄 알았던 작업이 거의 4시간 걸렸어요."

---

## Turn 4 — R-G-I-O + 주제 + 성공 기준

**User:**
```
진짜 문제 → R-G-I-O + 주제 1문장 + 성공 기준
```

**Assistant (요약 출력):**
- **R:** 현장 반장 김민수 — yard/feet 도면 + meter 견적·발주 동시 처리
- **G:** 도면 치수를 meter 기준으로 확정, 마감 전 제출
- **I:** 단위·기준 혼재 상태에서 손 변환 → 판정·재확인 과다, 숫자 어긋남
- **O:** 한 기준 확정 치수를 재작업·재설명 없이 일관 사용
- **주제:** 단위·기준 혼재 치수 손 변환 시 판정·재확인 비용과 오차 발생
- **성공 기준 4개:** 시간 30분 이내 / 판정 자체 가능 / 재발송·재설명 0회 / 기준별 숫자 구분·일괄 전달
